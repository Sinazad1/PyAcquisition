# alyPyAcquisition 
Application for collecting and analyzing conductivity measurements from multiple device under test (DUT) units with simultaneous IBP conductivity reference measurements during user designed protocols. Coefficients calculated from acquisition can also be programmed onto device within same program.

## Key Features

### Acquisition Mode
- Real-time graphing of conductivity and temperature measurements
- Acquisition of DUT units and IBP conductivity reference sensors simultaneously
- Automated protocol execution with multi-device control
- Pause/resume data acquisition
- Export to CSV for further analysis
- Logging of all device transactions 
- Configurable via external config.ini for compiled builds

### Analysis Mode
- Integrated file analysis ported in from original analysis scripts
- Legacy support for labview generated files
- Automatic matched record pairing (ie it finds event file matched with analysis file)
- Analysis Logging
- Implemented approval process per sensor
- Sensor calibration coefficients and approvals saved to coefficients file

### Programming Mode 
- loads coefficients file generated from analysis mode
- programs all coefficients onto target devices 
- filters programming to only those units that were approved. 
- Programming log - logs all transaction with device and summarizes end results.

## Requirements From Sina Zad, Diality 01/13/2026
- REQ-01	Architecture	Tech Stack: Application must be built using Python 3.x. The GUI framework must be PyQt or PySide (not Tkinter).
  - Already implemented
- REQ-02	Hardware	Instrument Control: System must control Syringe Pumps (Flow Rate) and Bath Temperature via serial/VISA drivers.
  - Already implemented
- REQ-03	Workflow	Acquisition Phase: User initiates test -> System actuates hardware -> System logs raw data to local CSV -> System saves file.
  - Already implemented
- REQ-04	Workflow	Analysis Phase (The "Black Box"): Upon completion of acquisition, the system must trigger a separate Analysis Script to process the data..
  - Implemented
- REQ-05	UI / Vis	Result Visualization: The GUI must display the output (graphs/images) generated by the Analysis Script for user review.
  - Implemented, however Aly Expects significant tuning will be needed by Diality especially as more empirical results come in.
- REQ-06	Data	Cloud Hook: The "Save/Commit" function must be modular. It needs a placeholder function (
    on_calibration_pass
    ) where Diality can insert Cloud upload code later.
  - Implemented; hooks put in for saving, concept of calibration pass would be on individual sensor level, so be very careful as implementation of this continues. 
- REQ-07	Safety	Error Handling: If hardware disconnects or stalls, the system must fail gracefully, stop all pumps, and log the error to a text file.
  - Safety was discussed with Sina and Dan of Diality 01/15/2026, emphasized that hardware is autonomous, ie maintained in present state by without any external software interaction. Software is configured to send stop commands on exit or abort. However, Aly recommends a physical, emergency stop button on any system where hardware operation represents a safety concern. 
- REQ-08	Config	Settings: All hardware parameters (COM ports, Timeouts, Limits) must be loaded from an external config file.
  - Already implemented
